# Todo API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver a Todo example with Result objects, FastEndpoints, secure accounts/permissions, global exceptions and architecture tests.

**Architecture:** Preserve Domain → Application → Infrastructure and WebApi composition. New owner-scoped Todo/User features use MediatR Result responses. Preserve legacy persistence and add new tables without destructive migration.

**Tech Stack:** .NET 10, MediatR 12.5.0, FluentValidation 12.2.0, FastEndpoints 8.3.0, ASP.NET JWT/Identity hashing, EF Core 10, xUnit.

**Spec:** docs/superpowers/specs/2026-10-11-todo-api-design.md

## Global Constraints

- Stay on net10.0; retain existing deployment and provider support.
- All new application requests return Result<T>; Domain has no framework references.
- Owner comes from validated JWT subject; foreign-owned IDs return 404.
- Server-side permissions fail closed; anonymous access only for register/login and operational endpoints.
- Preserve existing WorkItems table; migrations only add Users/TodoItems.
- Luna-only subagents. Work in the current Rider checkout on a task branch to keep IDE/CodeGraph available.

## Review Focus

- A valid token with another user's subject cannot read or mutate their Todos.
- Invalid token signatures, issuer, audience and expiration produce 401.
- Concurrent duplicate registration produces conflict without exposing database errors.
- Malformed payloads and invalid enum/UUID/due-date inputs produce ProblemDetails 400.
- Unexpected persistence exceptions produce sanitized 500; cancellation propagates.
